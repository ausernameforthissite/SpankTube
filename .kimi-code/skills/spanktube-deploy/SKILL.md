# Деплой SpankTube на Docker VM

При **каждом** деплое на `root@192.168.88.172` в `/root/spanktube` выполняй полную синхронизацию приложения, даже если изменился только один файл.

1. Скопируй на VM весь исходный код приложения со всеми backend-, web-, deploy- и docs-файлами. Не ограничивайся списком файлов, изменённых в текущей задаче: предыдущие изменения тоже должны попасть на VM.
2. Синхронизация должна учитывать удалённые из репозитория файлы, чтобы на VM не оставался устаревший код. Используй полное зеркалирование, например rsync с аккуратно ограниченным `--delete`, либо развёртывание полного архива в чистый каталог с последующим переключением на него.
3. Никогда не копируй и не перезаписывай секреты: `.env`, пароли, JWT-ключи, cookies, OAuth-секреты и учётные данные SOCKS5. Сохрани `/root/spanktube/deploy/.env` и другие секретные локальные конфиги на VM. Не применяй удаление к ним, томам PostgreSQL/RabbitMQ, NFS и другим пользовательским данным.
4. Исключай только VCS-метаданные, IDE-кэши и воспроизводимые артефакты сборки: `.git`, `.idea`, `.tooling`, `node_modules`, `dist`, `build`, `.gradle`. Не исключай исходники, тесты, манифесты, схемы БД, OpenAPI или документацию.
5. После полной синхронизации пересобери и перезапусти нужные контейнеры через существующий `deploy/docker-compose.yml`. Не полагайся на старый BuildKit cache как на доказательство актуальности исходников.
6. Проверь health-check сервисов и исходный пользовательский сценарий. При возможности подтверди совпадение исходников checksum или результатом, который ранее был связан с отсутствующим на VM кодом.
7. После Docker-деплоя проверь dangling-образы и выполни очистку по правилам `AGENTS.md`.
8. Если `df -h /` и `docker system df` подтверждают нехватку места, разрешено очистить неиспользуемый Docker Build Cache командой `docker builder prune -f` без отдельного запроса пользователя: это постоянное разрешение для такого случая. Проверь объём освобождённого места и итоговый `df -h /`. Контейнеры, образы работающих сервисов, тома PostgreSQL/RabbitMQ, NFS и секреты не затрагивай. После очистки не используй offline-сборку, пока кэш зависимостей не восстановлен обычной сборкой.

Если полная синхронизация ещё не завершена, деплой считается незавершённым. Не сообщай об успехе на основании одной сборки или частично скопированных файлов.

# SpankTube — карта проектной документации

Документ v0.6 разделён по частям приложения. Исходные разделы 1–70 сохранены полностью и встречаются ровно один раз в файлах ниже; их нумерация оставлена для ссылок и истории, а не для порядка чтения.

## Обязательный порядок работы

1. Определи по таблице область задачи и прочитай соответствующий файл **целиком**, а не только найденные поиском строки. Для межсервисных изменений прочитай все затронутые файлы.
2. Перед изменением архитектуры, ограничений или принятых решений дополнительно прочитай `design/00-overview.md`, особенно раздел 18. Не пересматривай принятые решения без явного указания пользователя.
3. Приёмка и известные ограничения находятся внутри тематических разделов вместе с реализацией. Не считай отдельные положительные результаты полной проверкой всего приложения.
4. При изменении поведения обновляй тематический файл и `AGENTS.md`. Новые разделы добавляй в подходящую тему с продолжением исходной нумерации (71, 72 и далее), не переписывая историю.

## Выбор файла по задаче

- `youtube-upstream-service`, NewPipe, метаданные, поиск, каналы, PO-токены: `01-upstream-and-metadata.md`; для сетевого транспорта также `06-infrastructure-and-operations.md`.
- `media-service`, Shaka, DASH/HLS, MP4/MKV, сегменты, скорость запуска: `02-media-and-playback.md`; для UI также `04-web-and-clients.md`.
- `archive-service`, очередь, MKV, NFS, версии, квоты, batch-архивация, запись эфира: `03-archive-and-library.md`; для прав доступа и модели данных также `05-security-data-and-api.md`.
- `catalog-service`, библиотека, ACL, история, API, PostgreSQL: `05-security-data-and-api.md` и `03-archive-and-library.md`.
- `gateway`, `user-service`, JWT, OAuth, пользователи: `05-security-data-and-api.md`; для сессии в браузере также `04-web-and-clients.md`.
- React, сессии, ссылки, плеер, меню, поиск, карточки, SSE: `04-web-and-clients.md`; для медиапотока также `02-media-and-playback.md`.
- Docker, Kubernetes, egress, DNS, nginx, инциденты и деплой: `06-infrastructure-and-operations.md`; для принятых архитектурных решений также `00-overview.md`.

Правила чтения из этого файла продублированы в `AGENTS.md`, который автоматически загружается Kimi Code при работе в репозитории.
